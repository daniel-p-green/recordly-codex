# Security policy

## Supported versions

Security fixes are applied to the latest version on `main` until a stable release line is established.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability-reporting feature for this repository when available. If private reporting has not been enabled yet, contact a maintainer privately through the repository profile and include:

- A clear description of the issue and affected component.
- Minimal reproduction steps or proof of concept.
- Security impact, including whether secrets, recording data, browser permissions, or arbitrary code execution are involved.
- Suggested mitigation, if known.

Do not include real credentials, cookies, customer data, or sensitive recordings in a report. We will acknowledge a valid report, investigate it, and coordinate disclosure before publishing a fix.

## Security boundaries

This project must not bypass site authentication, CAPTCHA, anti-bot protections, browser permission prompts, or user confirmations. Treat recordings and browser artifacts as sensitive by default and keep them outside the repository.

Observation remains unarmed until the broker durably accepts the first frame. A CDP main-frame document is locally eligible only when `id`, `loaderId`, `url`, and `securityOrigin` are nonempty and `securityOrigin` exactly equals the recording origin. Startup `Page.enable` may update this document identity, but a missing or mismatched field cannot request a challenge, create an isolated world, or emit evidence. Once armed, such a mismatch fails capture closed before challenge side effects.

For each eligible document epoch, the helper uses its already-authenticated loopback capability, session ID, fixed recording origin, positive integer epoch, and CDP document URL to request `/observer-challenge`. Before phase, challenge-count, or random-marker side effects, the broker requires the exact request keys, parses `documentUrl` with the platform `URL` canonicalizer, permits only `http:` or `https:`, rejects any username or password, and requires the resulting origin to equal both the fixed session origin and declared request origin. The broker returns a fresh 256-bit marker only after these checks and the durable baseline. Markers are generated in memory, never logged or persisted, and at most 32 challenges may be issued per capture. Exceeding the cap marks capture failed.

The start helper does not return success until the current epoch has both a successful isolated `Runtime.evaluate` with no exception details and an exact routed `{kind:"ready", nonce}` console handshake. The first valid 64-hex-character nonce is pinned to that epoch; later conflicting ready nonces are ignored. The nonce is created with isolated-world Web Crypto and exists in page code only inside the observer closure. Initial readiness has a 10-second hard limit. On timeout or startup failure, capture is marked failed; each observation-tail, retired-context cleanup, screencast stop, CDP detach, and broker failure-report step receives its own 250 ms best-effort teardown deadline so a stalled cleanup cannot hang startup indefinitely. Once armed, the generated Browser helper observes only trusted page-click coordinates/button and trusted-wheel-derived scroll position/deltas. Clicks require `event.isTrusted`. Generic or programmatic `scroll` events are not evidence: after a trusted `wheel`, the helper checks a bounded window of at most 120 animation-frame attempts spaced by 16 ms, roughly two seconds, and emits only the first nonzero resulting window position plus delta from the prior observed position. If that settlement window finds no movement, it emits no scroll evidence. No Runtime binding API or page main-world callable is exposed. The observer uses its captured `console.debug` and CDP `Runtime.consoleAPICalled` as the DevTools transport boundary. Observation does not collect selectors, element text, DOM, cookies, storage, headers, or the target URL path.

The CDP listener ignores every event that is not `debug` with exactly two direct-string arguments. The first argument must exactly match the current epoch's single marker; unmatched console noise and markers from retired epochs are ignored. For matching routes, the second argument must be a direct string of at most 4 KiB containing either the exact two-key ready envelope or an exact three-key `{kind:"event",nonce,event}` envelope with the pinned nonce and a non-array object event. Invalid routed payloads fail capture closed. Document identity A→B→A receives epochs one, two, and three with three fresh markers, so the old A marker/nonce cannot be accepted after returning to A. CDP `executionContextId` is diagnostic/non-gating. The helper strips both marker and nonce and sends only the bounded event through its one-time, loopback-only session capability. Neither value is sent to `/observed-event` or persisted in private or delivery artifacts. The broker validates the exact event schema and origin, applies body/rate/count limits, coalesces scroll bursts, assigns receipt timing, and writes to a private non-symlink file.

Observed-event delivery fails closed. An event before the first durable frame, missing persistence, malformed or zero-delta events, a malformed routed envelope, untrusted or programmatic input, wrong identity or origin, invalid capability, oversized bodies, flooding, unsafe files, missing main-frame document identity after arming, helper delivery failure, or matching-route console activity while the current navigation generation is not ready prevents capture approval. Navigation activation is serialized on a monotonically increasing generation. Repeated events for the same active or in-flight `{frameId, loaderId}` are idempotent and do not reinstall observation; a changed `loaderId`, even on the same frame, creates exactly one replacement generation. Stale work is retired and only the newest isolated context can become active. Before navigation, stop, or start-error teardown, the helper invokes the cleanup closure retained in isolated global state in the active or retired execution contexts. If navigation has already destroyed a context, the helper tolerates only the recognized stale-context error; other cleanup errors fail capture closed. Stop invalidates the current generation, waits for queued observation lifecycle work and retired-context cleanup, detaches the console observer, drains pending frame and observed-event work, and only then stops the screencast. Planned model telemetry cannot substitute for automatically observed evidence.

The renderer verifies every artifact-path ancestor beneath the session root as a real non-symlink directory, then requires each frame realpath to remain under the verified session realpath. A lexical path check or a regular leaf file alone is not sufficient.

Delivery output includes only sanitized observed action fields and CFR frame indices. Raw observed receipt timestamps and private event records remain local. Temporal visible-result alignment shows that a decoded visual change followed an observed action within a bounded window; it does not establish causation, page semantics, or objective completion.
