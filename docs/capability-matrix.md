# Capability matrix

This matrix describes the v0.2.0 release candidate. A capability is supported only when its stated prerequisites and approval gates pass.

| Area | Supported behavior | Evidence and approval boundary | Not supported or not proven |
| --- | --- | --- | --- |
| Host | Codex Desktop Browser runs generated start/stop helpers through `browser_run_code_unsafe` | A released marketplace install still needs a clean host acceptance check | Codex CLI or IDE browser control |
| Targets | Public or explicitly authorized, pre-authenticated origins | The session fixes its allowed origin set and validates Browser/broker origin identity | Authentication bypass, CAPTCHA, permissions, payments, sensitive uploads, publishing, deletion, access changes, or irreversible actions |
| Capture | CDP screencast frames flow directly from Browser to a loopback broker | Frames are durably written and acknowledged with broker-owned monotonic receipt offsets | Raw frames through model context, remote capture service, audio capture, or native-window capture |
| Automatic action evidence | Trusted page-click coordinates/button and trusted-wheel-derived scroll position/deltas are observed only after the first durable frame, same-origin document validation, and current epoch readiness | CDP must provide nonempty frame ID, loader ID, URL, and `securityOrigin` exactly equal to the recording origin; mismatch fails locally before challenge or isolated-world side effects. The authenticated broker independently parses `documentUrl`, permits only credential-free HTTP(S), and requires its canonical origin to match both session and request origins before incrementing the challenge count or generating the fresh nonpersistent 256-bit marker. The 33rd challenge fails capture. Start returns `observedReady: true` only after isolated evaluation succeeds without exception and an exact `{kind:"ready",nonce}` console handshake pins the first valid closure-only 256-bit nonce, with a 10-second readiness limit. Transport is isolated `console.debug` observed through CDP `Runtime.consoleAPICalled`; no binding APIs are used. Filtering requires `debug`, exactly two direct strings, exact current marker, payload at most 4 KiB, and exact ready or event shape. Unmatched console traffic, retired markers/nonces, and conflicting later ready nonces are ignored; malformed routed payloads and readiness-gap routed activity fail closed. A→B→A gets three epochs and cannot reuse A's first credentials. `executionContextId` is diagnostic/non-gating. Marker and nonce are stripped before broker event delivery and never enter artifacts. Startup failure gives each cleanup/report/detach step a 250 ms best-effort deadline. Click requires `event.isTrusted`; generic or programmatic `scroll` is ignored. After a trusted wheel, a bounded window of at most 120 animation-frame attempts spaced by 16 ms, roughly two seconds, emits the first nonzero resulting window position/delta; no movement produces no record. Navigation activation is generation-serialized; duplicate active or in-flight document events are idempotent, while a changed loader creates one replacement epoch. Stop invalidates activation, awaits lifecycle cleanup, detaches console observation, and drains pending frame/action work before stopping capture. Exact broker event schema, one-time capability kept out of injected code, loopback/origin checks, rate/count bounds, scroll coalescing, private persistence, and broker receipt timing remain required | Cross-origin, credential-bearing, non-HTTP(S), missing-identity, synthetic-click, programmatic-scroll, Runtime-binding, or pre-baseline/unready-generation evidence |
| Planned telemetry | MCP accepts model-described pointer, click, scroll, navigation, viewport, and marker notes | Useful as planning/context evidence only | Planned events cannot satisfy the observed-action approval gate |
| Temporal result QA | Each automatically observed action maps to the nearest CFR frame; decoded pre/result frames must show a thresholded visible change within the result window and retain a minimum final hold | Quality report states `temporal visible-result alignment; causal semantics are not asserted` | Causal attribution, semantic understanding, objective correctness, or guarantee that the observed action caused the visible change |
| Clipping/composition QA | Opening, midpoint, and final decoded samples compare source/output edge colors, border, matte, and aspect at the expected contain rectangle | Approval requires all clipping samples to pass fixed thresholds | General aesthetic judgment, OCR/layout correctness, or proof for frames outside the sampled set |
| Media QA | Deterministic 1920×1080, 30 fps, H.264 `yuv420p`, limited-range, silent CFR output | Probe, decodeability, duration/frame count, frozen-frame, final-state, artifact hash, privacy, temporal result, and clipping gates must pass | Audio, alternate codecs/profiles, variable frame rate, or editor-grade color management |
| Approval | Complete broker receipt timing, non-frozen evidence, automatically observed action/result alignment, final hold, clipping, media, hash, and privacy checks | Any failed required gate produces blocked or non-approved output | Approval from tool success alone, a planned event alone, or a merely decodable MP4 |
| Visual effects | Contained source framing with deterministic border and matte | Decoded composition is checked against source evidence | Cursor trails, click ripples, synthetic zooms, annotations, transitions, or a standalone shot-plan editor |
| Privacy and containment | Private session roots and event files; delivery manifest keeps origin, sanitized action fields/CFR indices, and hashes while omitting raw evidence paths and timestamps | Every artifact ancestor must be a real non-symlink directory and each frame realpath must remain under the verified session realpath. Raw frames, observed-event files, target path/query/fragment/credentials, DOM, and page text stay out of model context and delivery metadata | Visual redaction guarantee; authorized pages can still display sensitive pixels |

The v0.1.0 release proved the marketplace install and one authorized public workflow. v0.2.0 must repeat clean marketplace-install and approved-site acceptance checks after release; local tests and a bundle build are not substitutes.
