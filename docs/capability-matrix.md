# Capability matrix

This matrix describes the published and installed v0.3.0 release. A capability is supported only when its stated prerequisites and approval gates pass.

| Area | Supported behavior | Evidence and approval boundary | Not supported or not proven |
| --- | --- | --- | --- |
| Host | Codex Desktop Browser runs generated start/stop helpers through `browser_run_code_unsafe` | Browser is the interaction surface; the local MCP runtime coordinates capture and project operations | Codex CLI or IDE browser control |
| Targets | Public or explicitly authorized, pre-authenticated origins | The session fixes its allowed origin set and validates Browser/broker origin identity | Authentication or CAPTCHA bypass, permissions, payments, sensitive uploads, publishing, deletion, access changes, legal acceptance, or irreversible actions |
| MCP surface | Ten tools: five capture-session tools and five editable-project tools | Capture, sealed evidence, project, preview, and final are separate states | A tool result alone as proof of capture quality or editorial approval |
| Capture | CDP screencast frames flow directly from Browser to a loopback broker | Frames are durably written and acknowledged with broker-owned monotonic receipt offsets | Raw frames through model context, remote capture, native-window capture, or microphone/system-audio capture |
| Automatic action evidence | Trusted page-click coordinates/button and trusted-wheel-derived scroll position/deltas are observed only after the first durable frame, same-origin document validation, and current epoch readiness | Fresh nonpersistent marker and nonce credentials, strict console-envelope filtering, challenge/rate/count bounds, private persistence, and broker receipt timing are required | Cross-origin, credential-bearing, synthetic-click, programmatic-scroll, pre-baseline, or unready-generation evidence |
| Planned telemetry | MCP accepts model-described pointer, click, scroll, navigation, viewport, and marker notes | Useful as planning/context evidence only | Planned events cannot satisfy observed-action approval |
| Sealed delivery QA | Automatically observed actions map to CFR frames; decoded pre/result frames must show a bounded visible change and sufficient final hold | Probe, decodeability, frame count/duration, frozen-frame, final-state, artifact hash, privacy, temporal result, and clipping gates fail closed | Causal attribution, semantic understanding, objective correctness, general aesthetic judgment, OCR, or proof for unsampled frames |
| Editable project | A canonical full-document project has monotonic revisions, hashes, bounded automatic revisions, and stale-preview rejection | Project creation requires a quality-approved sealed capture; final rendering requires a preview of the same current revision | Collaborative merge editing, arbitrary patch operations, or a graphical timeline/editor |
| v0.2 sealed-delivery migration | An approved v0.2 delivery can seed a v0.3 project without recapture; absent cursor evidence becomes a hidden cursor and proportional screencast frames scale to sealed geometry | Migration trusts the private hash-verified sealed manifest and frame set, not a legacy `0644` capture-event log; incompatible geometry or evidence fails closed | Importing unapproved candidates, inferring missing cursor motion, or accepting arbitrary aspect changes |
| Timing and transitions | Clip trims, constant speed, linear speed ramps, cuts, and crossfades use deterministic source-to-output timing | Crossfades must fit both adjacent rendered clips; evidence and zooms remain mapped in absolute source time | Arbitrary easing curves, reverse playback, time remapping outside the declared model, or unsupported transition families |
| Cursor, click, and zoom | Source-keyed observed cursor samples, click ripple/bounce effects, and manual/automatic zoom regions render through trims, ramps, and crossfades | Visible effects require bounded source evidence that intersects a rendered clip; the renderer does not infer missing evidence | Fabricated action evidence, semantic target tracking, cursor trails, or unconstrained model-generated motion |
| Overlays and PiP | Authored annotations, captions, deterministic framing, and bounded binary-PPM PiP images | Text provenance/export disposition is validated; PiP is type-, size-, geometry-, and digest-checked before private staging | Arbitrary image/video formats for PiP, animated PiP, DOM-derived labels, or a visual-redaction guarantee |
| Audio | Bounded WAV tracks support source trim, output placement, and gain in MP4 | Audio is type-, size-, timing-, and digest-checked and consumed from a private snapshot | Browser/system audio capture, mixing beyond declared tracks, editor-grade audio processing, or audio in GIF |
| Formats and quality | Deterministic MP4 or GIF output with draft, standard, and high profiles | MP4 uses bounded H.264 encoding; GIF uses deterministic palette limits; output duration and frame stream are bounded | Alternate codecs, variable frame rate, alpha video, editor-grade color management, or format parity with every editor |
| Hooks | Declared metadata and watermark render-hook records survive the project contract | Hooks require the explicit local-render-hook permission/status contract | Arbitrary code execution or third-party plugin loading |
| Media integrity | Capture frames, PiP, audio, and render publication use private exclusive staging snapshots | The exact bytes copied from one opened regular file are bounded and digest/type checked; consumers use only the snapshot; cleanup runs on success/failure | Treating a previously hashed mutable pathname as trusted input |
| Privacy and containment | Private roots and event files; delivery metadata omits raw evidence paths/timestamps, target path/query/fragment, credentials, DOM, and page text | Ancestors and files are symlink/containment checked; sensitive artifacts use restrictive permissions | Visual redaction guarantee; authorized pages can still display sensitive pixels |

The public v0.3.0 release, installed server version, exact ten-tool surface, create/discard smoke, empty stderr, source-matching bundle SHA, and one authorized Recordly.dev capture-to-project workflow are verified. This proves the bounded path above, not arbitrary-site autonomy or unlisted capabilities.
